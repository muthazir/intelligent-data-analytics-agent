        Ingest
        The browser posts the CSV to FastAPI /upload.
        
        
        Understand
        Headers are normalised, synonyms mapped and the schema detected.
        
        
        Validate
        Values are pre-cleaned, validated and cleaned.
        
        
        Store
        SQL Server IDAA_DB keeps every dataset in its own scope.
        
        
        Analyse
        pandas computes the metrics and flags Z-score anomalies.
        
        
        Narrate
        Gemini rewrites the facts, or a deterministic narration is used.
        
        
        Deliver
        The saved result feeds this dashboard and the PDF.
        
      
        
      
        
        
        
          
        Database
        
          
        
            
        Dataset
        One row per upload, for every schema.
        
            
        DatasetCustomer, DatasetProduct
        Customers and products scoped to a single dataset.
        
            
        EcommerceOrder
        Order rows. Composite foreign keys keep them inside their own dataset.
        
            
        AnalysisRun
        One per analysis, with the full result JSON and the narration source.
        
            
        Anomaly, Insight
        The flagged rows and narrated sentences of each run.
        
          
        
          
        Cafe and gym rows stay in the cleaned CSV. Their datasets and runs are stored in SQL Server.
        
        
        
        
        
          
        Facts before narration
        
          
        Every number is computed by Python. Gemini only rewrites those facts as sentences, and any sentence containing a number that is not in the facts is discarded.
        
          
        Without a Gemini key, IDAA writes a deterministic narration from the same facts and labels it as such.
